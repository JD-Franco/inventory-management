Data Flow — Filter Request Lifecycle

1
User selects a filter

FilterBar.vue updates shared refs in useFilters() — e.g. selectedLocation.value = 'San Francisco'. All views share the same composable instance (singleton).

2
View reacts and fetches

Each view watches the filter refs. On change it calls loadData(), which reads getCurrentFilters() and calls the relevant api.* method with the active filter object.

3
API client builds query string

api.js builds URLSearchParams, skipping any value equal to 'all'. Sends e.g. GET /api/orders?warehouse=San+Francisco&category=sensors&month=2025-01.

4
Backend filters in-memory

apply_filters() runs sequential list comprehensions over the loaded JSON data (warehouse → category → status). filter_by_month() handles both YYYY-MM and quarter strings like Q1-2025. All matching is case-insensitive.

5
Pydantic validates & serializes

FastAPI validates each item against the declared response_model (e.g. List[Order]). Invalid or missing fields raise a 422. The validated list is serialized to JSON and returned.

6
Vue renders filtered data

The view stores the response in a ref (e.g. orders.value = response). Computed properties derive stats, charts, and table rows. Templates use v-for with unique keys to efficiently diff and re-render only what changed.
